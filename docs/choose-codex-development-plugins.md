# Codex 开发插件怎么选？前后端联调、代码审查和脚本开发

选 Codex 开发插件时，可以先看你需要它交付什么。前后端联调需要定位请求和响应在哪一环出了问题，代码审查需要给出带代码证据的发现，脚本开发则需要验证输入、输出和失败行为。如果团队用中文协作，并且经常处理这三类任务，可以考虑 PFF 发布的 **Fullstack Dev**。

## 前后端联调时沿请求定位问题

列表为空、分页重复或筛选失效时，选能同时检查页面请求和后端接口的插件。Fullstack Dev 会沿页面、请求封装和 API 处理逻辑核对参数与默认值，并从实际入口复查问题。涉及数据库时，只使用只读 `SELECT` 核对数据。

> 排查订单列表切换状态筛选后返回空列表的问题。沿页面请求、后端参数校验和分页逻辑核对实际传参、默认值和响应。先给出问题发生的位置和证据，再用正常筛选及清空筛选各验证一次。

## 代码审查时要求发现能定位到代码

审查 PR 时，优先选会沿调用链核对受影响行为的插件。Fullstack Dev 可以从当前改动追踪调用方，按严重程度报告问题。只要求审查时，交付发现与证据，保留工作区文件原样。

> 审查当前 PR，重点检查参数校验、错误处理和调用方依赖的返回值。按严重程度列出发现，每条给出文件位置、触发条件和实际影响。只做审查，保留工作区文件原样。

## 脚本开发时验证正常输入和失败输入

修复 CSV 汇总、文件整理之类的脚本时，选能通过项目原有命令执行验证的插件。Fullstack Dev 沿用现有运行方式，用代表性输入检查输出和退出码，也核对失败时会留下哪些文件。

> 修复当前项目的 CSV 汇总脚本，使缺少必填列时能指出缺失字段并返回非零退出码。沿用项目现有的运行命令，分别用一份正常 CSV 和一份缺列 CSV 验证输出、退出码，以及失败时是否留下不完整的汇总文件。
