# 代码审查与审计

## 取证范围

- 审查从用户指定的 PR、提交、改动或文件入手。未指定时先看工作区和暂存区的改动，均为空时看最近一次提交。沿改动追踪调用者、被调用者和相关测试，尤其核对接口、返回值和行为变更对现有调用方的影响。
- 审计从用户指定的模块或目录入手，未指定时检查全仓。先查说明、构建和部署配置、依赖、入口及测试，再沿主要业务路径追踪数据流。大型仓库优先深入鉴权、支付、数据写入、后台任务和共享状态等关键路径，并注明覆盖范围。

## 判断与交付

- 优先检查结果错误、回归、安全、数据丢失和预期负载下的故障。再看高风险路径缺少验证、实际性能瓶颈和可以确认的冗余。依据仓库的用法与部署配置判断负载，缺少依据时标明假设。
- 每条发现都要有代码证据、可发生的输入或场景、具体影响和最小修复建议。判定代码可删除前，核对调用方、配置、测试、样例和动态引用。已注明适用范围的简化，只有实际使用超出范围或有独立问题时才作为发现。
- 只要求审查或审计时，保持代码和配置原样。按严重程度给可定位到文件和行的编号发现，说明应优先处理的事项、已验证和未核查的部分。没有发现时，交代实际核查范围。
